## 1. 背景与目标

### 背景

- Agent Panel 当前定位为本地 agent 资产管理面板（Sessions、Skills、MCP、Hooks 等只读浏览）
- 团队同事使用 Claude Code CLI 存在门槛：终端操作不直观、上下文切换频繁、新人上手困难
- 开源项目 OpenCovibe 已验证"GUI 包装 CLI 子进程"模式可行

### 目标

| 维度 | 目标 |
|------|------|
| 核心体验 | 在 Session Detail 页内直接与 Claude Code 对话，体验对标 CLI 当前版本 |
| 配置模式 | P0 复用 CLI 已有认证；P1 支持独立配置 API Key / Base URL |
| 跟随更新 | 用户本地 claude CLI 升级后，新功能自动可用，无需 agent-panel 改代码 |
| 可扩展性 | 架构预留自定义功能口子（输入拦截、输出增强），本期不实现 |
| 长远兼容 | Transport 层抽象，未来可接入 SSH 远程（手机访问场景） |

### 非目标（本期不做）

- 自定义 slash 命令 / 中文"、"转 slash
- SSH Remote Transport
- 多 Provider 切换 UI
- API Key 独立配置界面（默认继承 CLI 已有认证）
- 会话分叉 (fork)

## 2. 用户画像与场景

### 用户画像

| 类型 | 特征 | 痛点 |
|------|------|------|
| CLI 新手 | 对终端不熟悉，不会 vim/快捷键 | 看不懂 CLI 输出，不知道怎么交互 |
| 效率型开发者 | 熟悉 CLI，但频繁切换窗口 | 想在一个界面看历史 + 继续对话 |
| 团队管理者 | 关注同事的 session 产出 | 想快速查看 session 后直接续上讨论 |

### 核心使用场景

1. **新建对话**：在项目下直接新开一个对话，不需要打开终端
2. **查看历史后继续对话**：在 session list 浏览后，点进 detail，看完历史消息，直接在底部输入框继续提问
3. **中断后续接**：上次在 CLI 里的对话，现在想在 GUI 里继续（等价于 `claude --resume`）
4. **实时观察 AI 工作**：看到 Claude 的流式输出、工具调用、文件修改，像看直播一样
5. **审批权限请求**：Claude 要执行危险操作时，在 GUI 中点按钮批准/拒绝

## 5. 核心交互流程

### 5.1 续接对话流程

```
用户进入 Session Detail
    ↓
看到历史消息（只读，和现在一样）
    ↓
底部显示 [▶ 连接并继续对话] 按钮
    ↓
用户点击 → 按钮变为 loading spinner + "连接中..."
    ↓
后端 spawn `claude --output-format stream-json --input-format stream-json --verbose --permission-prompt-tool stdio --include-partial-messages --resume <session-id>`
    ↓
spawn 成功 → 状态变为"已连接"，底部变为输入框
    ↓
用户输入消息 → 前端通过 WebSocket 发给后端 → 后端写入 CLI stdin
    ↓
CLI stdout 流式返回事件 → 后端解析 → WebSocket 推送前端 → 实时渲染
    ↓
用户点击 [断开] → 确认后 kill CLI → 状态回到离线
用户关闭页面/刷新 → 进入 30 秒重连窗口，超时后 kill CLI
```

### 5.2 消息发送流程

1. 用户在输入框键入文本
2. 按 Enter 或点击发送按钮
3. 前端立即在消息流底部渲染一条"user"气泡（乐观更新）
4. 通过 WebSocket 发送 `{ type: "user_message", text: "..." }` 给后端
5. 后端将文本写入 CLI stdin（stream-json input 格式）
6. 输入框清空，发送按钮变为 [■ 停止]
7. 收到第一个 assistant token → 开始渲染 AI 回复

**AI 响应期间的输入行为**：
- 输入框**不禁用**，用户可以继续打字准备下一条消息
- 在 AI 响应中发送消息 → 消息进入后端队列，当前 turn 结束后自动处理
- 后端保证一次只有一个 turn 写入 CLI，排队由后端 SessionActor 管理

### 5.3 中断/停止流程

触发方式（对标 CLI 的 Esc 键行为）：
1. 点击 [■ 停止] 按钮
2. 按键盘 Esc 键（单次即可）

中断后：
1. 后端向 CLI stdin 写入 interrupt control_request
2. CLI 中断当前生成，返回 result（可能含 error）
3. 后端将其归一化为 `state_change: { state: "idle", reason: "interrupted" }` 发给前端
4. 消息流中标记"已中断"，已生成的文本保留可见
5. 用户可立即输入新消息继续对话

## 6. 会话连接状态机

### 状态定义

| 状态 | UI 表现 | 用户可操作 |
|------|---------|-----------|
| `idle` | 灰点 + "离线"，底部显示 [连接] 按钮 | 点击连接 |
| `connecting` | 转圈 + "连接中..."，按钮 disabled | 点击取消（变回 idle） |
| `connected` | 绿点 + "已连接"，底部显示输入框 | 输入消息、点击断开 |
| `disconnecting` | 转圈 + "断开中..."，输入框 disabled | 无 |
| `error` | 红点 + 错误信息，底部显示 [重试] 按钮 | 点击重试 |

### 状态转换

```
idle ──[用户点击连接]──→ connecting
connecting ──[spawn 成功]──→ connected
connecting ──[spawn 失败]──→ error
connecting ──[用户取消]──→ idle
connected ──[用户点击断开]──→ disconnecting
connected ──[CLI 正常退出]──→ idle（自动刷新历史消息）
connected ──[CLI 异常退出]──→ error
disconnecting ──[kill 完成]──→ idle
error ──[用户点击重试]──→ connecting
```

### 并发防护规则

1. **Epoch 机制**：每次触发状态变更时递增 epoch，后端只响应最新 epoch 的请求
2. **操作互斥**：同一 session 的 connect/disconnect 操作用 Mutex 串行执行
3. **快速切换**：用户连续点击 连接→断开→连接，中间操作被 epoch 过滤，只有最后一次生效
4. **页面切换不断开**：用户切换到其他页面时，后台连接保持，CLI 进程不 kill
5. **主动断开需确认**：用户点击断开按钮时，弹出确认弹窗后再执行
6. **App 关闭提醒**：关闭 app 窗口时，如果有活跃连接，弹出"还有正在运行的对话，确认退出？"

## 7. 消息流式渲染规则

### 7.1 渲染分区

消息流分为两个区域：

| 区域 | 数据来源 | 渲染方式 |
|------|---------|---------|
| 历史区 | Session JSON 文件（现有逻辑） | 虚拟列表，一次性加载 |
| 活跃区 | WebSocket 实时事件 | 直接 DOM 追加，不虚拟化 |

两区之间用一条分隔线标记："── 以下为本次对话 ──"

### 7.2 流式文本渲染

- Assistant 文本按 token 追加到当前 message block
- 使用 Markdown 增量解析（不要每个 token 重新 parse 全文）
- 未完成的 code block 暂时不高亮，完整后再触发高亮
- 光标闪烁动画表示正在生成

### 7.3 Tool Call 渲染

tool_use 和 tool_result 事件流程：

```
[tool_use_start] → 渲染 ToolCard 骨架（工具名 + spinner）
[input 累积]    → 逐步填充参数预览
[tool_use_end]  → ToolCard 进入 "执行中" 状态
[tool_result]   → ToolCard 展示结果（成功/失败）
```

复用现有 `ToolCard` / `BashCard` / `EditCard` 等组件，新增 "执行中" 状态（spinner + 进度）

### 7.4 滚动行为

| 场景 | 行为 |
|------|------|
| 用户在底部 | 自动跟随滚动（新消息始终可见） |
| 用户往上翻阅 | 停止自动滚动，显示 [↓ 新消息] 浮标 |
| 点击浮标 | 平滑滚动到底部，恢复自动跟随 |
| AI 回复结束 | 如果不在底部，浮标闪烁提示 |

### 7.5 回复结束后的处理

1. 收到 `state_change: { state: "idle" }` 事件（turn 正常结束或中断）
2. 将活跃区消息合并到历史数据（更新虚拟列表数据源）
3. 触发 session JSON 文件重新加载（确保数据持久化一致）
4. Turn Sidebar 追加新的 turn entry

## 8. Slash 命令与自动补全

### 8.1 触发条件

- 输入框内容以 `/` 开头时，弹出 Slash 菜单浮层
- 输入框为空时按 `/` 键，也触发

### 8.2 菜单结构

```
┌────────────────────────────────┐
│ 会话       /status /context    │
│ 编码       /review /test       │
│ 配置       /model /config      │
│ Skills     /movie /train-ticket│
│ 其他       /help /clear        │
└────────────────────────────────┘
```

- 命令列表来源：CLI 初始化时的 `system/init` 事件中携带的 slash_commands 元数据
- 分类参考 OpenCovibe 的分组逻辑，按 session/coding/config/skills/other 分组
- 支持模糊搜索过滤：输入 `/mo` 只显示 `/model`、`/movie`

### 8.3 交互细节

| 操作 | 行为 |
|------|------|
| ↑/↓ 方向键 | 在命令列表中移动高亮 |
| Enter | 选中当前高亮命令，填入输入框 |
| Escape | 关闭菜单，保留已输入内容 |
| 继续输入 | 实时过滤命令列表 |
| 鼠标 hover | 移动高亮 |
| 鼠标点击 | 选中命令 |

### 8.4 子命令

部分命令有子交互：
- `/model` → 弹出模型选择下拉框
- `/permission-mode` → 弹出模式选择
- 其他命令直接发送给 CLI 执行

### 8.5 命令执行结果

- 有些命令有即时反馈（如 `/status` 返回状态信息）
- 反馈在消息流中渲染为特殊的"系统消息"样式（区别于 user/assistant）

## 9. 权限交互与工具审批

### 9.1 触发时机

Claude CLI 在以下情况会暂停等待用户批准：
- 执行 Bash 命令（非 allowlist 中的）
- 写入/编辑文件
- 访问网络资源
- 使用 MCP 工具

### 9.2 UI 展示

权限请求在消息流中 inline 渲染为一张卡片：

```
┌─────────────────────────────────────────┐
│ 🔒 权限请求                              │
│                                          │
│ 工具: Bash                               │
│ 命令: rm -rf ./build                     │
│                                          │
│ [✓ 允许]  [✗ 拒绝]                       │
└─────────────────────────────────────────┘
```

### 9.3 交互行为

| 操作 | 效果 |
|------|------|
| 允许 | 发送 allow 响应给 CLI，卡片变为"已批准"（置灰） |
| 拒绝 | 发送 deny 响应，卡片变为"已拒绝" |
| 超时（无操作） | 卡片保持等待，CLI 阻塞直到用户操作 |

> "始终允许此类操作"按钮列为 P1（涉及 permission rules 持久化到 settings.json）。

### 9.4 批量审批

当多个权限请求同时到达时：
- 堆叠显示多张卡片
- 提供 [全部允许] 快捷按钮
- 防止双击：点击后按钮立即 disabled

### 9.5 Hook 回调

CLI 的 PreToolUse hook 也可能产生需要确认的卡片，渲染逻辑与权限相同，但标题为"Hook 审核"。

## 10. 异常与边界场景

### 10.1 进程异常

| 场景 | 处理 |
|------|------|
| CLI spawn 失败（未安装 claude） | error 状态 + 提示安装指引 |
| CLI 运行中崩溃 | error 状态 + 显示 stderr 信息 + [重试] 按钮 |
| CLI 输出非法 JSON | 跳过该行，继续解析后续事件 |
| API Key 无效/额度不足 | CLI 自身会报错，渲染为 error 消息 |

### 10.2 并发场景

| 场景 | 处理 |
|------|------|
| 快速连接→断开→连接 | epoch 机制，中间操作被丢弃 |
| 在 A session 连接中切换到 B session 页面 | A 的连接保持后台运行，不断开 |
| 同一 session 在 CLI 和 GUI 同时打开 | GUI 的 resume 会创建新的 CLI 实例，两者独立运行（CLI 自身支持） |
| 多个浏览器 tab 打开同一 session | 只允许一个 tab 连接，其他 tab 显示"已在其他窗口连接" |

### 10.3 页面生命周期

| 场景 | 处理 |
|------|------|
| 用户切换页面（detail→list→其他） | 连接保持，后台继续运行，不中断 |
| 用户关闭浏览器 tab | WebSocket 断开 → 后端等待 30 秒重连 → 超时 kill CLI |
| 用户刷新页面 | WebSocket 重连 → 如果 CLI 仍活跃则恢复事件流 |
| 用户主动点击断开 | 确认弹窗 → 确认后 kill CLI → idle |
| App 窗口关闭且有活跃连接 | 弹出确认提醒 → 确认退出则 kill 所有活跃 CLI |
| App（agent-panel-server）崩溃 | kill_on_drop 确保子进程被杀；下次启动扫描孤儿 PID |
| 网络断开（WebSocket 丢失） | 前端自动重连；后端保持 CLI 运行等待重连 |

### 10.4 长对话性能

| 场景 | 处理 |
|------|------|
| 活跃消息区累积很多消息 | 每轮结束后合并回虚拟列表，活跃区清空 |
| 单条消息超长（大段代码输出） | 折叠 + "展开全部"按钮，和现有逻辑一致 |
| 频繁 token 更新导致重渲染 | 文本区用 ref 直接操作 DOM，不走 React state |

## 11. 配置与设置

### 11.1 P0 配置策略

P0 不做独立配置 UI，直接继承 CLI 已有的认证和配置：
- API Key：使用 `claude auth` 已配置的认证（CLI 自身管理）
- 模型：使用 CLI 默认模型，或通过 `/model` slash 命令切换
- 权限模式：使用 CLI 默认，或通过 spawn 参数覆盖

唯一需要的配置项：

| 配置项 | 类型 | 说明 |
|--------|------|------|
| `claude_binary_path` | string | claude CLI 路径（选填，默认 `claude`，自动 PATH 查找） |

### 11.2 P1 完整配置（后续）

P1 阶段增加 Settings 页面的"对话设置" tab：

### 11.3 首次使用引导

用户首次点击 [连接] 时：
1. 检测 `claude` CLI 是否存在
2. 如果不存在 → 提示安装指引
3. 检测 CLI 是否已认证（`claude auth status`）
4. 如果未认证 → 提示用户先在终端运行 `claude auth login`

## 12. 验收标准

### 功能验收

- [ ] 在 Session Detail 页可以点击连接，成功续接现有 session
- [ ] 输入消息后，AI 回复实时流式渲染（token 级）
- [ ] Tool call（Bash、Edit、Read 等）正确渲染为卡片，显示执行状态和结果
- [ ] 权限请求弹出卡片，点击允许/拒绝后 CLI 继续执行
- [ ] 输入 `/` 弹出命令菜单，方向键选择，Enter 执行
- [ ] 点击断开后，CLI 进程被正确 kill，状态回到离线
- [ ] 关闭页面/tab 后，后端无孤儿进程

### 体验验收

- [ ] 连接/断开有 loading 动画，无卡顿感
- [ ] 长对话流畅滚动，无明显掉帧
- [ ] AI 流式输出时，用户往上翻阅不会被强制拉回底部
- [ ] 快速连接→断开→连接不会导致状态错乱
- [ ] 输入框获得焦点后，常用快捷键正常工作（Ctrl+A 全选等）

### 兼容验收

- [ ] Claude CLI >= v2.1.100 正常工作（低版本提示升级）
- [ ] 未安装 claude CLI 时，给出清晰安装引导
- [ ] CLI 已认证状态下可正常对话（复用 `claude auth` 配置）
- [ ] 所有现有 Session Detail 功能不受影响（搜索、Turn 导航、收藏等）
